# 计划台 · 双人

> 一个给两个人用的日程工作台。解决的不是"我要更高效"，而是"我什么时候找她，才不算打扰"。

## 这个项目解决什么问题

异地 / 各自忙的时候，最难的不是沟通，是**不知道对方现在在干什么**。

- 她今天在自习还是在休息？
- 这周她有几件事压着？
- 我这时候发消息，会不会正好打断她背书？

这些问题的答案，散在聊天记录里、散在"你忙吗"的试探里。问一次是关心，问三次就变成负担。

**计划台**把"她接下来的安排"变成一张两个人共享的、看得懂的图：

- 她今天有什么要做的、做完了没有
- 她这周的重心在哪（四象限一眼看出）
- 她今天心情怎么样、吃了什么、去了哪
- 更重要的是——**我不用问，就知道现在适不适合打扰她**

它是给"两个人"做的，不是给"一个人管理别人"做的。所以两边权限完全对等：谁都能建计划、打卡、留言、看对方的安排。

## 功能

### 1. 双人房间：一条链接只属于一对人

工作台是同一份代码、同一个发布地址，但**每一对使用者的数据互相看不见**。

第一次打开会引导「创建我们的空间」或「输入房间码」。创建后得到一个 8 位房间码，把它发给对方，对方输入即绑定。

隔离不是在浏览器里藏起来，而是**在服务端完成的**：每张表都有「房间号」字段，所有查询都带 `filter`，别人的记录根本不会被下载到你的设备上。打开开发者工具也看不到。

换设备、清缓存都不影响——房间码和身份记在本地，丢了重新输一次房间码即可恢复。

### 2. 四象限计划 + 双形态任务

按「重要 / 紧急」四象限组织，颜色区分优先级。每个计划可以是：

- **待办**：勾掉就完成
- **量化**：有总量和单位（背 2000 个单词、读 440 页书），打卡累加进度

支持**中文自然语言写日期**——输入框里直接写「明天下午 练习单摆」「下周周三 复盘会议」，自动识别日期并从标题里剥离。这是日常最高频的操作，不该逼用户去点日期选择器。

### 3. 今天要处理

首屏置顶。自动汇总：

- 逾期没完成的（红色标注）
- 今天该做的
- 快到期的

昨天没做完的自动顺延到今天，不会凭空消失。

### 4. 照片日记 + 下挂聊天

每天可以传一张照片，配上「今日做了 / 今日吃了 / 今日评价 / 心情 / 评分 / 标签」。

照片下面可以聊天，而且**聊天是挂在"这一天的照片"上的**——不是全局消息流。看到对方发的晚饭，直接在下面回一句，上下文不会散。

### 5. 心情记录

八档心情（超开心 / 开心 / 平静 / 疲惫 / 焦虑 / 难过 / 烦躁 / 崩溃），月历热力图 + 快捷打卡。

### 6. 周复盘

每周记「保持 / 问题 / 尝试 / 下周预案」，两个人各自写，互相能看到。

## 技术实现

**单文件 HTML，零外部依赖。** 所有 CSS、JS、SVG 图标、SVG 图表全部内联，不引用任何 CDN / 框架 / 字体 / 图表库。

这样做的原因很实际：如果页面引用了外部 JS 库，用户存下 HTML 之后库 404，功能全废。单文件意味着**双击就能打开，断网也能用**。

几个自己比较满意的实现：

| 实现 | 说明 |
|---|---|
| 中文自然语言日期解析 | 支持「明天 / 后天 / 下周周三 / 3 月 5 号 / 2026-03-05」等写法，识别后从标题里剥离，剩下的才是任务名 |
| 照片下挂聊天，零改表 | 聊天表复用「关联计划」字段，存 `rel = 'photo:2026-10-23'`。不新增表、不改 schema，就把全局留言变成了按天挂载 |
| 离线操作队列 | 断网时的增删改进入 `pending` 队列，恢复后自动补写；重复操作有去重 |
| 四象限 × 待办/量化双形态 | 同一套数据模型支持"勾选完成"和"累加进度"两种语义，UI 自动切换 |
| 全内联 SVG 图表 | 进度环、月历热力图、柱状图都是手写 SVG，无图表库 |
| 服务端多租户隔离 | 7 张表统一加「房间号」字段，`db.query` 带 `filter`，过滤在服务端完成；写入端由 `stampRoom()` 统一盖戳，漏写不可能 |

数据层：7 张数据表，通过 WorkBuddy 资料库 / 智能页 SDK 做云端同步；localStorage 作为离线缓存与降级方案。

> 一个实测细节：`filter` 对**空值**不匹配。所以给已有表加「房间号」字段后，历史数据必须做一次迁移补上房间号，否则一开过滤就会集体"消失"——数据还在表里，但页面拉不到。

## 如何运行

### 方式一：直接打开

```
双击 build2/output.html
```

无需安装、无需构建、无需联网。此时会自动进入**演示模式**：载入内置示例数据、所有交互照常可点，但数据只存在内存里（刷新即还原），也不会写入你的真实缓存。

也可以用 `?demo=1` 强制作演示：`build2/output.html?demo=1`。

### 方式二：完整体验（含双人同步）

通过在线链接打开：<https://workbuddy.link/p/3M1oqPyAJKYDSeGpFdvw7k?hideWorkBuddyButton=1>

双人同步依赖平台注入的数据库 SDK，**必须在支持该 SDK 的环境里运行**。

> 如果你在微信里打开链接发现同步不生效：微信会把页面切到小程序壳里，SDK 不存在。此时页面会自动降级为演示模式，请点右上角「···」→「在浏览器打开」恢复真实同步。

## 目录结构

```
build2/
  parts/                 # 源码，按层拆分
    01_head.html         # <head> + 全部 CSS
    02_body.html         # DOM 结构
    03_js_a.js           # 常量 / 状态 / 工具 / 解析层
    04_js_b.js           # 数据层（读写云端 + 本地缓存 + 离线队列）
    05_js_c.js           # 渲染层 / 交互层 / 初始化
  build_check.py         # 拼接 parts → output.html，并抽出 JS 做语法校验
  test_run.js            # jsdom 冒烟测试（5 个场景 × 16 条断言）
  verify_local.py        # 产物完整性体检（体积 / 标记 / 敏感串）
  migrate_room.py        # 加「房间号」字段后的历史数据迁移
  normalize_table_ids.py # 表 ID 字面量收敛为 TABLE 映射
  schema_*.json          # 7 张表的结构定义
  output.html            # 构建产物（可直接打开）
多租户与网站化方案.md      # 房间隔离方案与平台能力实测记录
评审优化清单.md            # 代码评审问题清单与修复状态
```

构建与测试：

```bash
python build2/build_check.py     # 拼接 + 语法校验
node build2/test_run.js          # 冒烟测试（需 jsdom）
python build2/verify_local.py    # 产物体检
```

冒烟测试覆盖 5 个场景：有数据 / 空数据 / 无 SDK（离线）/ 微信内置浏览器 / 普通浏览器。每个场景跑 16 条断言，同时监听 `window.onerror` 与 `unhandledrejection`。

## 数据与隐私

- 每对使用者有独立**房间码**，7 张表的查询全部带服务端 `filter`——别人的记录不会被下载到你的设备。
- 业务数据存在云端数据表里；本地缓存存在浏览器 localStorage，不上传第三方。
- 支持导出 / 导入 JSON 备份，数据可自行带走。
- 仓库内不含任何真实姓名、手机号、密钥、照片或聊天记录。演示数据均为占位内容。
- 身份只是本机的一个标记，不是账号；没有密码体系，也就没有"密码泄露"这回事。房间码才是访问凭据，请像对待口令一样保管。

> ⚠️ **想把本项目部署成自己的实例，必须换掉 `build2/parts/03_js_a.js` 顶部的 `TABLE` 映射**（7 个数据表 ID）与 `DATABASE_ID`。仓库里保留的是作者的示例表 ID，直接复用会把两拨人的数据写进同一批表。

## 已知限制

- 双人同步依赖 WorkBuddy 平台 SDK：纯前端无法自建实时同步通道。脱离平台时会自动降级为演示模式（本地示例数据），功能可完整体验但不同步。
- 微信内置浏览器会把页面切到小程序壳，SDK 不可用；需在系统浏览器打开。
- 照片以 base64 存在数据表里，上传时先压到长边 900px 的 JPEG；照片量大时首次加载会变慢（离线缓存有 3.2MB 上限，超出部分只在联网时可见）。
